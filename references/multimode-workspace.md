# 多模式文稿工作介面與 16:9 學術簡報模式

本文件是「全能文稿排版助手」衍生版新增的工作介面規格，不是對上游 Guizang PPT 原始功能的逐項宣稱。上游模板提供 Editorial／E-ink、Swiss／Grid 與簡報演講控制資源；本專案另將這些風格整合到一個可操作的多模式文稿工作介面。

## 為什麼需要這項功能

只有「預設 16:9」或「提供 16:9 投影片」不等於擁有 16:9 學術簡報模式。模式必須以可見、可操作的工具列入口呈現，使用者能從履歷、研究報告、教學材料等目前內容，切換至另一種呈現方式。

Google AI Studio 不會因為 System Instructions 提到 GitHub 路徑，就自動把倉庫內的 HTML、CSS 或 references 載入模型上下文。因此，AI-STUDIO-INSTRUCTIONS.md 也必須內含完整行為要求；本檔與 assets/multimode-document-studio-template.html 是可供 Agent 參考的規格／範例。

## 必要工具列

當使用者要求生成、設計、編輯或呈現可互動的文稿／簡報網頁、預覽工作區或 HTML 成品時，頂端需顯示固定且響應式的工具列，至少包含以下四種互斥模式與三項操作：

1. **瑞士國際網格（風格 B）**：重視網格、數據、比較、流程、明確的對齊與資訊層級。
2. **雜誌電子墨水（風格 A）**：重視敘事、文字節奏、留白、引文與編輯式層次。
3. **教學與工作坊（風格 C）**：重視學習目標、任務步驟、時間、產出、評量與回饋。
4. **16:9 學術簡報模式**：把相同的核心內容轉換成 16:9 投影片畫布／逐頁簡報，不能只是把原本的單頁文件縮放或改成橫向。

另必須提供：

- **CRAP 檢核報告**：可開啟檢核面板，列出 Contrast、Repetition、Alignment、Proximity 的具體檢查項目、問題、修正及複查狀態。未實際檢查的項目標示「尚未檢查」，不可預設全部通過。
- **列印／PDF**：實際呼叫瀏覽器列印功能（例如 window.print()），並提供列印 CSS；不可把 HTML 冒稱為已生成 PDF。
- **下載單檔 HTML**：提供實際可點擊的下載按鈕，產生可保存的完整 HTML。若聲稱為單檔，所需 CSS／JavaScript 與必要內容必須內嵌；對無法內嵌的遠端字型、圖片或資源要說明依賴。

## 互動必須真的運作

- 四種模式是可操作的按鈕／分頁控制，不是只有裝飾的標籤。顯示目前作用中的模式，維持鍵盤焦點及適當的 ARIA 狀態。
- A／B／C 模式切換應保留同一份內容資料，但按各自設計系統重新組織版面；不得混用互不相容的模板 class。
- 16:9 模式切換到真正逐頁簡報結構。每頁具 16:9 比例、頁碼／總頁數、上一頁／下一頁控制及鍵盤左右鍵翻頁；需要時提供總覽與返回。
- 內容只維護一份真實資料來源或共享狀態，再輸出到各模式，避免某個模式漏掉最新修訂或出現互相矛盾的數字。
- CRAP 面板顯示實際查核結果與未完成項目，不可只列出原則名稱，也不能未查核就宣稱通過。
- 列印時隱藏工作列、操作按鈕及非必要控制；16:9 模式應逐頁列印，避免將多頁內容擠在一張紙。
- 下載前將必要 CSS／JavaScript 納入輸出 HTML，保留目前文件內容與功能；不要提供空殼檔、只有模板的檔案或無法運作的下載按鈕。
- 工具列在窄螢幕上應能換行或水平捲動，不得遮住內容。

## 內容與模式規則

- 若內容來自履歷、研究報告、論文或課程材料，不可為了適配投影片而捏造、刪改關鍵事實、統計數字、引用或研究結論。
- 投影片模式需要重新規劃每頁的溝通目的，一頁聚焦一個主要訊息；詳細文字可以保留在其他模式或演講者備註中。
- 如果來源內容不足以支持某一頁，標示「待補資料」或省略該主張，不得自行補造。
- 對於純文字問答、非視覺文稿任務，或使用者明確要求不要介面／只要原始內容時，不強制建立此工具列。

- [ ] 16:9 模式有多頁投影片、頁碼、上一頁／下一頁與鍵盤操作。
- [ ] CRAP 報告可以開啟，未檢查狀態沒有被偽裝成通過。
- [ ] 列印／PDF 按鈕會開啟列印流程，列印樣式合理。
- [ ] 下載單檔 HTML 按鈕會產生實際可保存、保留功能的檔案。
- [ ] 手機／窄視窗下工具列及內容可用。
