# 完整成品交付檢核表

本清單補強全能文稿排版助手的三種完整交付模式：履歷／CV、研究報告、附完整原始碼的簡報專案。請依任務使用，不要求每個專案都產出所有種類。

## A. 履歷／簡歷／CV

- [ ] 先確認用途與地區慣例：求職履歷、學術 CV、個人簡介或作品集。
- [ ] 所有學歷、經歷、日期、職稱、成果、技能、獎項、出版品和連結皆有使用者資料支持。
- [ ] 不虛構量化成效、職責、資格、語言程度或不存在的作品。
- [ ] 依目標職務／學術場景安排資訊順序，刪減重複而非刪掉關鍵事實。
- [ ] 重要資訊易於掃讀；日期、標點、動詞時態、格式與名稱一致。
- [ ] 需要 ATS 相容時，提供單欄、語意明確、少用圖示／文字方塊的版本。
- [ ] 明確標示尚待使用者補充的資料，不以猜測填空。
- [ ] 檢查頁面長度、斷行、日期順序、聯絡資訊及輸出格式。

## B. 研究報告／專題報告

- [ ] 標題、作者／單位、日期、版本等必要中繼資料已確認或標為待補。
- [ ] 依報告目的建立完整章節架構，必要時包含摘要／執行摘要、目錄、背景、目的、方法、結果、討論、限制、結論、建議、參考文獻與附錄。
- [ ] 章節順序符合論證邏輯，不為套模板而製造不存在的研究階段或結論。
- [ ] 數據、引文、表格、圖表、單位、時間／樣本範圍及來源可追溯。
- [ ] 區分事實、使用者觀點、分析、推論與未驗證事項。
- [ ] 參考文獻與正文引用互相對應；缺失資訊標為待補，不自行編造。
- [ ] 表格與圖表有標題、圖說、單位、必要註解與來源。
- [ ] 檢查章節完整性、標題層級、頁碼／目錄（若有）、跨頁表格與列印版面。
- [ ] 交付可編輯的實際檔案或完整內容，並說明尚未驗證的格式項目。

## C. 簡報附完整原始碼／可再製專案

- [ ] 明確區分簡報成品、原始碼、素材／資料與使用說明。
- [ ] 交付的程式檔完整，沒有省略號代替實作、空函式、虛構檔案或「自行補上」佔位內容。
- [ ] 若使用多檔案結構，提供完整檔案樹與所有必要檔案，例如 HTML、CSS、JavaScript、資料檔、素材、設定檔與測試。
- [ ] 提供 README，說明專案用途、功能、檔案結構、需求、安裝、執行／建置、操作方式、測試方式與限制。
- [ ] 外部套件、字型、圖片、資料及 API 的來源、版本、授權與設定方式清楚；不得提交 API key、密碼或其他機密。
- [ ] 需要套件管理時提供對應設定檔與鎖定檔（視工具與專案而定），並記錄可重現的執行方式。
- [ ] 若宣稱可測試，提供真實可執行的測試或檢查指令；未執行時不得宣稱測試通過。
- [ ] 若使用者要求開源，提供授權選擇。使用者未指定時，清楚提出授權建議並標示假設；不可自動將本 Skill 的授權套用到所有產出，也不可忽略上游素材／依賴的授權條件。
- [ ] 簡報內容與程式碼版本一致；變更、資料來源與已知限制寫入 README。
- [ ] 若工具能產生檔案，優先提供完整資料夾或 ZIP；若不能，逐檔提供完整內容與精確路徑，不能只給片段。
- [ ] 分開標示已執行的程式檢查、已在瀏覽器實測的功能，以及尚未驗證的部分。

## D. 通用最終交付

- [ ] 交付項目與使用者要求逐項對應。
- [ ] 不以「已完成」代替實際檔案、完整文字或可用程式碼。
- [ ] 清楚列出假設、待補資料、來源與驗證限制。
- [ ] CRAP 的 C／R／A／P 完成兩輪檢查，並附有實際依據。

## v2.1.0：上游模板使用證據

- [ ] 確認執行環境實際讀取了 `assets/template.html` 或 `assets/template-swiss.html`，而不是只看見 GitHub URL 或提示詞中的路徑。
- [ ] 確認使用對應的 `layouts*.md`、`themes*.md` 及必要元件／演講者模式規格。
- [ ] 確認交付的 HTML 保留選定模板的實際 DOM、CSS、JS 與翻頁／講者互動；若只做 CSS 仿風格，明確標示為衍生風格而非完整上游模板。
- [ ] 若在 AI Studio 工作，確認完整模板已作為檔案／專案上下文加入；System Instructions 文字本身不算已載入原始碼。
- [ ] 五種產品風格切換是衍生版功能，不宣稱為上游原生五套完整模板。
